# Практическая работа 3

## 1. Числа как байты

| Значение | Байты | Hex |
| :--- | :--- | :--- |
| 1 | 01 00 00 00 | 0x00000001 |
| -1 | FF FF FF FF | 0xFFFFFFFF |
| 1000 | E8 03 00 00 | 0x000003E8 |
| 1000000 | 40 42 0F 00 | 0x000F4240 |

Байтов всегда 4. Число 1000000 выглядит длиннее, но в памяти это те же 4 байта. Потому что int всегда 4 байта.

## 2. Переполнение
Гипотеза: думаю `int.MaxValue + 1` будет отрицательным, потому что перейдет границу.

| Выражение | Результат |
| :--- | :--- |
| `int.MaxValue` | 2147483647 |
| `int.MaxValue + 1` | -2147483648 |
| `int.MinValue` | -2147483648 |
| `int.MinValue - 1` | 2147483647 |

| Значение | Байты |
| :--- | :--- |
| `int.MaxValue` | FF-FF-FF-7F |
| `int.MinValue` | 00-00-00-80 |

Объяснение: процессор складывает нормально, но результат не влезает в 32 бита. Поэтому старшие биты теряются, и число перескакивает на другое.

## 3. Текст как байты

| Текст | Символов | Байтов | Байты |
| :--- | :--- | :--- | :--- |
| Hello | 5 | 5 | 48 65 6C 6C 6F |
| Привет | 6 | 12 | D0 9F D1 80... |
| Пробел | 1 | 1 | 20 |

Вывод: у английских букв 1 символ = 1 байт. У русских 1 символ = 2 байта. Поэтому количество разное.

## Ответы на вопросы
1. int всегда 4 байта, потому что это такой тип. Он не меняется.
2. int.MaxValue + 1 стал отрицательным, потому что перешел границу и места больше нет.
3. Процессор складывает нормально, но результат не влезает в int. Это ограничение типа, а не ошибка.
4. Hello и Привет разные, потому что английские буквы 1 байт, а русские 2 байта.
5. Unicode символов очень много, поэтому нужно больше 8 бит. Поэтому 1-4 байта.

## Дополнительное задание
Если тип больше (`byte`, `short`, `int`, `long`), то он занимает больше байтов (1, 2, 4, 8). Больше значений - больше байтов надо. N битов дают 2^N значений.
